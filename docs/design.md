## 四、业务流程、接口与事件设计（30 分）

### 4.1 报价、叫车与接单

- 正常过程：获取报价 → 发起叫车 → 匹配司机 → 确认接单。
- 主要异常分支：至少讨论无人接单；结合已确认规则补充报价过期、超时或重复请求等必要分支。
- 待补充：时序图、业务规则、各服务处理职责、结果及对应契约。
- 时序图源建议：`docs/diagrams/quote-request-match.mmd`，尚未创建。

### 4.2 取消与重新叫车

- 正常过程：申请取消 → 处理相关费用 → 通知结果 → 重新叫车。
- 主要异常分支：至少讨论取消与接单冲突，并说明最终状态和费用结果由谁决定。
- 待补充：时序图、业务规则、各服务处理职责、结果及对应契约。
- 时序图源建议：`docs/diagrams/cancel-rebook.mmd`，尚未创建。

### 4.3 接驾、上车与支付

- 正常过程：司机到达上车点 → 确认并上报乘客已上车 → 开始行程 → 结束行程 → 生成费用 → 完成支付。
- 主要异常分支：至少讨论支付失败，并说明状态、重试及通知结果。
- 待补充：时序图、业务规则、各服务处理职责、结果及对应契约。
- 时序图源建议：`docs/diagrams/pickup-trip-payment.mmd`，尚未创建。

每张时序图需列出客户端、参与的微服务及外部系统，区分请求、响应和消息的先后顺序以及同步/异步交互。箭头标注具体接口、方法或事件名，并与契约逐项一致。
