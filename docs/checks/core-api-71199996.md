## 本卡处理的问题

1. 第 3 章 422 与现有 400/409 冲突：统一 400 输入错误、409 业务/状态/版本/幂等冲突；具体 code→status 可机读。
2. 原公共 409 例子固定为 QUOTE_EXPIRED：改为逐操作适用错误的共享示例引用，付款/位置等不再展示错误的报价例子。
3. 核心流程已覆盖，辅助资料、在线状态、位置会话/上报、通知、运营入口缺少 HTTP 定义：补 8 个客户端操作。
4. 内部调用只有逻辑名：补 16 个服务端点、允许调用者、scope、服务身份与委托要求；取消事实直接引用事件数据 Schema。
5. getOperationResult 只约束结果并集，方法类型可能与返回体不符：新增按 operationType 限定结果类型，并纳入 3 个辅助写入的恢复归属。REJECTED 必须携带明确拒绝的错误，不能错误地放 UNKNOWN。
6. 后台事实扫描补齐稳定 cursor、nextCursor 与 hasMore；不能用预分配 ID 或客户端时间跳过尚未提交的事实；先持久 Job 再推进检查点。
7. 明确本地截止任务/支付状态机不公开 HTTP；外部适配器只定义本组 IO，供应商路径和签名参数留到真实选型，不编造已经接通。

没有更改已有三条流程的图源、导出图、事件 Schema/示例、权威状态机或定价规则；现有业务请求/成功响应 Schema（操作恢复除外）保持。README 和报告更新当前阶段与第 4.4 节入口。
