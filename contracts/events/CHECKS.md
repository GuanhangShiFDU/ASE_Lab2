## 如何复查字段与示例

只查看文档、执行交接脚本或提交 PR 不需要 Python、Docker、RabbitMQ。以下是可选的静态检查，需 Python 3.9+，在仓库根目录执行；虚拟环境建议放在仓库外：

```bash
python3 -m venv "$HOME/lab2-contract-check-env"
"$HOME/lab2-contract-check-env/bin/python" -m pip install -r contracts/events/requirements-check.txt
"$HOME/lab2-contract-check-env/bin/python" contracts/events/validate.py
```

Windows Git Bash 使用 `python` 建环境，环境内解释器路径替换成 `Scripts/python.exe`。检查器读取本地 Schema/示例，不访问业务服务。修改契约后应重跑，并额外审查 Schema 无法证明的状态迁移、来源身份、归属、幂等和并发约束。制包时额外构造的 12 个错误输入属于静态边界检查，不是部署后的故障注入。

## 评审重点

1. 司机轮询约 5 秒与 15 秒邀请是本组时效取舍，差网络下不保证送达；截止由 S-02 控制。
2. 过时状态投影可忽略，但旧的未处理计费事实不能因序号小被丢弃。
3. 费用待生成、支付 UNKNOWN 和通知失败分开处理，均不能撤销已提交履约事实。
4. 消费者先持久保存结果/任务后 ACK；外部通知/付款依靠自己的持久任务和幂等关联恢复。
5. 第 2 章若在评审中改变服务名、实体归属或字段口径，须同步本章和事件契约；未合并不等于不能并行设计，也不等于已获所有成员确认。
