## 核心接口需要说明什么

- 用途、提供服务及调用方。
- 路径/方法或 RPC 名、输入输出、字段约束、调用示例及错误码。
- 身份与权限控制、版本约定。
- 对存在重试或重复提交风险的操作，明确幂等规则、作用范围和重复请求结果。
- 与哪些业务实体、状态迁移和时序图步骤对应。

HTTP 接口使用 OpenAPI YAML/JSON；gRPC 使用 `.proto`；WebSocket 等方式明确消息类型、方向及字段。其余接口可在报告中简述用途与输入输出。

## 协作约定

- 先确定业务含义和服务所有者，再填写契约。
- 契约与 [设计报告](../docs/design.md)、数据模型和时序图一起评审。
- 统一 ID、字段、状态及事件命名；必要时在上下文术语表中解释差异和关联。
- 示例使用虚构数据，不填写真实用户信息、凭据或密钥。
- 不把空文件、占位符或待确认内容标为接口已经完成。

格式参考：[OpenAPI 3.1.0 规范](https://spec.openapis.org/oas/v3.1.0.html)。
